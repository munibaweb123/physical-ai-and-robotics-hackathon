# EdDSA Authentication Setup Guide

This guide explains the EdDSA authentication implementation and how to test it with your Neon database.

## Overview

The authentication system has been updated to use **EdDSA (Ed25519)** algorithm instead of HS512:

- **Auth Server** (Node.js/TypeScript): Better Auth with EdDSA JWT signing
- **Python Backend** (FastAPI): EdDSA JWT verification
- **Database**: Neon PostgreSQL

## Architecture

```
┌─────────────────┐         EdDSA JWT        ┌──────────────────┐
│                 │  ────────────────────>    │                  │
│   Auth Server   │                           │ Python Backend   │
│  (Better Auth)  │  <────────────────────    │    (FastAPI)     │
│                 │      JWKS (Public Key)    │                  │
└────────┬────────┘                           └─────────┬────────┘
         │                                              │
         │                                              │
         └──────────────────┬───────────────────────────┘
                            │
                    ┌───────▼────────┐
                    │                │
                    │ Neon Database  │
                    │  (PostgreSQL)  │
                    │                │
                    └────────────────┘
```

## What Changed

### 1. Auth Server (auth-server/src/auth.ts)
- ✅ Changed JWT algorithm from `HS512` to `EdDSA`
- ✅ Removed `secret` parameter (EdDSA uses asymmetric keys)

### 2. Crypto Utilities (auth-server/src/crypto-utils.ts)
- ✅ Created EdDSA key pair generation
- ✅ Automatic key loading/generation on startup
- ✅ Keys saved to `.env` file

### 3. JWKS Endpoint (auth-server/src/index.ts)
- ✅ Updated to expose EdDSA public key in JWK format
- ✅ Returns proper OKP (Octet Key Pair) format for Ed25519

### 4. Python Backend (auth/core.py)
- ✅ Prioritized EdDSA verification
- ✅ Uses JWKS to fetch public key
- ✅ Falls back to HS algorithms if needed

## Installation & Setup

### 1. Install Dependencies

**Auth Server:**
```bash
cd auth-server
npm install
```

**Python Backend:**
```bash
pip install cryptography pyjwt httpx fastapi
```

### 2. Start the Auth Server

```bash
cd auth-server
npm run dev
```

On first run, you'll see:
```
⚙ Generating new EdDSA key pair...
✓ EdDSA keys saved to .env file
```

### 3. Start the Python Backend

```bash
python main.py
```

Or with uvicorn:
```bash
uvicorn main:app --reload --port 8000
```

## Testing the Authentication Flow

### 1. Test JWKS Endpoint

```bash
curl http://localhost:10000/api/auth/jwks
```

Expected response:
```json
{
  "keys": [
    {
      "kty": "OKP",
      "use": "sig",
      "alg": "EdDSA",
      "kid": "better-auth-eddsa-key",
      "crv": "Ed25519",
      "x": "<base64url-encoded-public-key>"
    }
  ]
}
```

### 2. Test User Registration

```bash
curl -X POST http://localhost:10000/api/auth/sign-up/email \
  -H "Content-Type: application/json" \
  -d '{
    "email": "test@example.com",
    "password": "Test123456!",
    "name": "Test User"
  }'
```

### 3. Test User Login

```bash
curl -X POST http://localhost:10000/api/auth/sign-in/email \
  -H "Content-Type: application/json" \
  -d '{
    "email": "test@example.com",
    "password": "Test123456!"
  }'
```

Save the returned JWT token from the response.

### 4. Test Protected Python Endpoint

```bash
curl -X POST http://localhost:8000/chat \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <your-jwt-token>" \
  -d '{
    "user_query": "What is this book about?",
    "mode": "standard"
  }'
```

## Troubleshooting

### Issue: "No JWK found for EdDSA token"

**Solution:** Ensure the auth server has started and generated keys. Check the auth-server logs for:
```
✓ EdDSA keys saved to .env file
```

### Issue: "EdDSA token verification failed"

**Solution:**
1. Verify the JWKS endpoint is accessible from the Python backend
2. Check that the public key in JWKS matches the private key used for signing
3. Ensure the Python backend has the `cryptography` package installed

### Issue: "Database connection failed"

**Solution:**
1. Verify the `NEON_DATABASE_URL` is correct in auth-server/.env
2. Check that SSL is enabled in the connection string
3. Ensure your Neon database is active (not paused)

### Issue: "Token expired" errors

**Solution:**
- Tokens expire after 7 days by default
- Re-authenticate to get a new token
- Adjust `expiresIn` in auth.ts if needed

## Security Notes

1. **Private Keys**: The `EDDSA_PRIVATE_KEY` in `.env` should NEVER be committed to git
2. **Production**: Use proper secrets management (AWS Secrets Manager, HashiCorp Vault, etc.)
3. **HTTPS**: In production, always use HTTPS for auth server and Python backend
4. **Key Rotation**: Implement key rotation for long-term deployments
