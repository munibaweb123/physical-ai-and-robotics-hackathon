Feature Specification: Physical AI & Humanoid Robotics

1. Feature Name​

Physical AI & Humanoid Robotics Specifications

2. Description​

This document outlines the detailed technical specifications for the environment, software, middleware, AI/VLA dependencies, and project workspace structure required for the Physical AI & Humanoid Robotics projects. It serves as a foundational specification for setting up development and deployment environments.

3. User Scenarios​

Scenario 1: Setting up a Project Environment​

  • As a student/developer, I want to set up my development environment, so that I can work on Physical AI and Humanoid Robotics projects efficiently.
    • Steps:
      1. The user refers to this specification for environment requirements (OS, drivers, software).
      2. The user installs/configures the specified operating system, drivers, and compute stack.
      3. The user installs the required software and middleware components (ROS 2, Simulation Engines, AI/VLA dependencies).
      4. The user sets up their project workspace according to the defined structure.
      5. The environment is ready for Physical AI and Humanoid Robotics development.

4. Functional Requirements​

FR1: Environment Specifications​

  • Primary OS: The system MUST operate on Ubuntu 22.04 LTS (Jammy Jellyfish).
    • Rationale: Native support for ROS 2 Humble and NVIDIA Isaac Sim.
  • Kernel: The system SHOULD use Linux Kernel 5.15 or later. A Real-time kernel (PREEMPT_RT) is OPTIONAL but RECOMMENDED for physical robot control.
  • Restricted OS:
    • Windows 10/11: ONLY allowed if using WSL2 (Windows Subsystem for Linux) strictly for pure code logic. NOT RECOMMENDED for GUI-heavy simulation (Isaac Sim/Gazebo).
    • macOS: NOT SUPPORTED due to NVIDIA CUDA and Isaac Sim incompatibilities.
  • NVIDIA Driver: The system MUST have NVIDIA Driver Version 535.xx or higher (Production Branch).
  • CUDA Toolkit: The system MUST have CUDA Toolkit Version 12.2 installed.
  • Docker: Docker Engine 24.0+ with nvidia-container-toolkit MUST be configured.

FR2: Software & Middleware Stack​

  • Robot Operating System (ROS):
    • Distribution: The system MUST use ROS 2 Humble Hawksbill (LTS).
    • Build System: The system MUST use colcon.
    • Middleware Implementation: The system SHOULD use rmw_cyclonedds_cpp (preferred over FastDDS for high-bandwidth video data).
  • Simulation Engines:
    • NVIDIA Isaac Sim: Version 2023.1.1 or later.
      • Requirement: Requires Omniverse Launcher.
    • Gazebo: Gazebo Fortress (Ignition).
    • Unity: Unity 2022.3 LTS + URDF Importer package.
  • AI & VLA Dependencies:
    • Python: Version 3.10 (Default in Ubuntu 22.04).
    • Key Libraries:
      • torch (PyTorch with CUDA support).
      • ultralytics (YOLOv8 for object detection).
      • openai-whisper (Local inference for voice commands).
      • langchain (For orchestrating LLM cognitive planning).

FR3: Project Workspace Structure​

  • All student projects MUST adhere to the standard ROS 2 workspace overlay system, with a structure similar to: 
    ~/physical_ai_ws/
    ├── src/
    │   ├── humanoid_description/ # URDF/SDF assets, meshes, visual materials
    │   ├── humanoid_control/ # ROS 2 Control hardware interfaces
    │   ├── humanoid_navigation/ # Nav2 configuration (behavior trees, maps)
    │   ├── humanoid_perception/ # Isaac ROS pipelines (VSLAM, AprilTags)
    │   └── humanoid_agent/ # VLA integration (LLM logic, Whisper)
    ├── build/
    ├── install/
    └── log/

5. Non-Functional Requirements​

(Not explicitly defined in user input, but implicit in environment setup goals)

NFR1: Compatibility​

  • The chosen software and hardware components MUST be compatible with each other as specified.

NFR2: Performance​

  • The environment MUST be capable of running GUI-heavy simulations (Isaac Sim/Gazebo) smoothly.

NFR3: Maintainability​

  • The project workspace structure SHOULD be consistent across all student projects for ease of maintenance and collaboration.

6. Success Criteria​

  • A student/developer can successfully install all specified environment, software, and middleware components.
  • NVIDIA Isaac Sim and Gazebo simulations run without significant performance degradation.
  • ROS 2 packages can be built and executed within the specified environment.
  • AI/VLA dependencies are correctly installed and functional for development.
  • Project workspaces are organized according to the defined structure.

7. Key Entities​

Environment​

  • Operating System (Ubuntu 22.04 LTS)
  • Kernel (Linux 5.15+)
  • NVIDIA Driver (535.xx+)
  • CUDA Toolkit (12.2)
  • Docker (24.0+)

Software & Middleware​

  • ROS 2 Humble Hawksbill
  • colcon
  • rmw_cyclonedds_cpp
  • NVIDIA Isaac Sim (2023.1.1+)
  • Gazebo Fortress
  • Unity 2022.3 LTS
  • Python 3.10
  • PyTorch
  • ultralytics (YOLOv8)
  • openai-whisper
  • langchain

Project Workspace​

  • physical_ai_ws (ROS 2 workspace)
  • ROS 2 Packages (humanoid_description, humanoid_control, humanoid_navigation, humanoid_perception, humanoid_agent)

8. Assumptions​

  • Users have basic Linux command-line proficiency for environment setup.
  • Network access for downloading software dependencies is available.
  • Hardware meets minimum specifications, particularly for GPU.
  • The specified versions of software and drivers are compatible.

9. Open Questions​

No specific open questions requiring clarification at this stage, as the input is highly prescriptive.
