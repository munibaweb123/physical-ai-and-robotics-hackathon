Execution Plan: Physical AI & Humanoid Robotics

1. Feature Name​

Physical AI & Humanoid Robotics Execution Plan

2. Goal​

To guide the setup of a development environment and the implementation of key functionalities for Physical AI and Humanoid Robotics projects, as defined in the associated Feature Specification.

3. Technical Context​

This plan outlines the concrete steps for establishing the required operating system, driver stack, software, and middleware for Physical AI and Humanoid Robotics development. It details a phased approach from foundational environment setup to advanced VSLAM, Navigation, and LLM integration for embodied intelligence.

Tech Stack Overview​

  • OS: Ubuntu 22.04 LTS (with specific Kernel and NVIDIA Driver requirements)
  • Compute: NVIDIA CUDA 12.2, Docker with nvidia-container-toolkit
  • Middleware: ROS 2 Humble Hawksbill, colcon, rmw_cyclonedds_cpp
  • Simulation: NVIDIA Isaac Sim 2023.1.1+, Gazebo Fortress, Unity 2022.3 LTS
  • AI/ML: Python 3.10, PyTorch, YOLOv8 (ultralytics), OpenAI Whisper, Langchain

4. Constitution Check​

The "Physical AI & Humanoid Robotics Execution Plan" is in strong alignment with the project's updated Constitution (Version 1.1.0).

  • Course Identity: Directly supports the goal of bridging the gap between digital and physical AI, providing the foundational environment for controlling Humanoid Robots.
  • Overview & Philosophy: The plan's emphasis on simulation-to-reality and embodied intelligence directly reflects the core philosophy.
  • Curriculum Modules: The plan breaks down the environment and software setup needed to address each module (ROS 2, Digital Twin, AI-Robot Brain, VLA).
  • Hardware Constitution: The plan explicitly leverages the "Digital Twin" Workstation and "Physical AI" Edge Kit hardware requirements by guiding the installation of necessary drivers and software for these platforms.
  • Operational Models: The plan details the setup for both Workstation and Edge Kit, which are central to the defined operational models.

5. Execution Phases​

Phase 0: The Iron Foundation (Weeks 0-1)​

Objective: Establish the compute infrastructure before software deployment. Deliverable: A dual-environment setup (Workstation + Edge) communicating over SSH.

Step 1: Workstation Setup ("The Digital Twin")​

  • OS Installation: Clean install Ubuntu 22.04 LTS on the workstation.
    • Critical: Do not use "Safe Graphics" mode during install; it conflicts with NVIDIA drivers later.
  • Driver Stack:
    • Install NVIDIA Driver 535.xx (via Software & Updates > Additional Drivers).
    • Install CUDA 12.2 Toolkit.
    • Verify with nvidia-smi (Ensure GPU is visible).
  • Simulation Core:
    • Install Omniverse Launcher.
    • Download Isaac Sim 2023.1.1 (or latest 4.x if compatible with provided assets).
    • Run ./isaac-sim.sh to cache shaders (Expect 10-15 min wait time on first launch).

Step 2: Edge Kit Setup ("The Physical Brain")​

  • Flashing: Flash JetPack 6.0 to the NVMe SSD of the Jetson Orin Nano.
    • Note: JetPack 6.0 includes Ubuntu 22.04, eliminating the need for Docker containers for basic ROS 2 usage.
  • Network:
    • Assign a Static IP (e.g., 192.168.1.100) to the Jetson.
    • Add the Workstation and Jetson IPs to the /etc/hosts file on both machines for name-based resolution.

Phase 1: The Nervous System (Weeks 2-5)​

Objective: Enable communication between software nodes and physics engines. Deliverable: A robot model spawned in simulation reachable by ROS 2 topics.

Step 3: Middleware Installation (Both Machines)​

  • Install ROS 2 Humble: sudo apt install ros-humble-desktop
  • Environment Configuration: Add source /opt/ros/humble/setup.bash to ~/.bashrc.
    • Crucial: Set export ROS_DOMAIN_ID=42 (or unique ID per student) on both machines to prevent crosstalk in the lab.
  • Install build tools: sudo apt install python3-colcon-common-extensions.

Step 4: The Workspace Overlay​

  • Create the standard directory structure: 
    mkdir -p ~/physical_ai_ws/src
    cd ~/physical_ai_ws
    colcon build
  • Asset Import: Clone the course repository into src/. Import the Humanoid USD (Universal Scene Description) files into Isaac Sim.

Phase 2: Perception & Control (Weeks 6-10)​

Objective: Give the robot eyes and the ability to move. Deliverable: A robot that detects objects and walks to them in simulation.

Step 5: Visual Slam (VSLAM)​

  • Isaac ROS Install: On the Workstation (Sim) and Jetson (Real), install NVIDIA Isaac ROS GEMs.
  • Deploy isaac_ros_visual_slam node.
  • Sensor Bridge: In Isaac Sim: Enable the "ROS 2 Bridge" extension. Map the Simulated Camera USD output to the /camera/color/image_raw ROS topic.

Step 6: Navigation (Nav2)​

  • Mapping: Teleoperate the robot in Sim to generate a 2D Occupancy Grid.
  • Planning: Launch the nav2_bringup stack. Tune the costmaps (inflation radius) to account for the humanoid's arm span, not just its feet.

Phase 3: Embodied Intelligence (Weeks 11-12)​

Objective: Integrate the LLM "Brain" to command the "Body." Deliverable: Voice-commanded autonomy.

Step 7: VLA Integration​

  • Whisper Node: Run openai-whisper on the Jetson (use the tiny.en or base.en model for latency speed).
  • LLM Planner: Run the "Cognitive Node" (Python) which takes text prompts and outputs behavior tree XMLs or action sequences.
  • Testing:
    • Command: "Go to the kitchen and find the apple."
    • Verify: LLM converts to -> Maps_to(kitchen) -> detect_object(apple).

Phase 4: Sim-to-Real Transfer (Week 13)​

Objective: Deploy code from the RTX Workstation to the Jetson Orin. Deliverable: Capstone Demo.

Step 8: The Reality Gap​

  • Calibration: Calibrate the physical RealSense camera; update the URDF xacro file with the precise mounting offset.
  • Safety Constraints: Apply a velocity_smoother filter to the ROS 2 controller to prevent jerky movements on the physical motors.
  • Deployment:
    • Copy the install/ folder from Workstation to Jetson (or recompile on Jetson if architecture differs significantly).
    • Run the robot_bringup.launch.py.
